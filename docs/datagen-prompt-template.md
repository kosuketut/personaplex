# 日本語ロールプレイ台本生成プロンプト（PersonaPlex 形式）

対象スクリプト: `generate_scripts.py`（このファイルの本文・スキーマ・例は同スクリプトから機械的に書き出したもの。`make_template_md.py` で再生成できる）。

## 推奨設定

| 項目 | 値 |
|---|---|
| モデル | `Qwen/Qwen3-30B-A3B-Instruct-2507-FP8`（Apache-2.0）。GPU を共有していて空きが約 35 GiB 未満なら `Qwen/Qwen3-14B-AWQ --gpu-mem 0.6`（Apache-2.0） |
| 推論 | vLLM 0.11.0 + torch 2.8.0+cu128（ドライバ 570 で動作確認）。`LLM.chat` のオフラインバッチ。`chat_template_kwargs={"enable_thinking": False}` |
| 構造化出力 | vLLM の guided decoding（`GuidedDecodingParams(json=schema)`、backend は auto で xgrammar が選ばれた）。ターン数の上下限は台本ごとにスキーマの minItems/maxItems で強制 |
| サンプリング | temperature 0.8、top_p 0.9、top_k 40、max_tokens 3000、要求ごとに seed = `--seed`×100003+i |
| メッセージ構成 | system = 下の「システムメッセージ」、user = シナリオ別テンプレート + 出力例。**システムメッセージの中身を捨てるチャットテンプレート（llm-jp-3.1 instruct4 がそう）では、スクリプトが自動で検出し user の先頭に連結する** |

## 決めたこと（規約）

- **数字の表記**: system_prompt と facts はオペレータが打つ形で算用数字（「営業時間は7時から22時まで」）。turns も算用数字＋助数詞で、読み上げたとおりに書く（「7時半」「1050円」「10パーセント」）。「:」「〜」「-」「/」「%」「,」などの記号は使わない。パイロットと同じく、単語時刻を作るときに `pyopenjtalk.run_frontend` が漢数字に直す前提。数字同士の間の「〜」は `sanitize()` が「から」に置き換える。
- **相槌（backchannel）**: 聞き手が相手の発話の途中に打つ短いターン。相手の発話を2つに割り、その間に置く（相手 → 相槌 → 同じ相手）。自分の答えの前置きの「はい」は相槌にしない。
- **割り込み（interruption）**: user のターンだけ。直前の agent の発話は言いかけで終わる。モデルが文を言い切ってしまった場合は `sanitize()` が後半の最後の「、」で切るか、文末の句読点を落とす（`cut_off_by_sanitize: true` が付く）。
- **固有名詞の多様性**: 店名・業種・担当者名・客の名前・用件・話題・人物設定・ターン数・割り込みの有無は、スクリプト側でプールから `--seed` で決める。LLM が作るのは残りの事実と会話だけ。名字 約150、店名の語 約80 × 業種 32。
- **Moshi に入るのは system_prompt だけ**: facts は検査用。facts の値は system_prompt にそのまま入っていなければならない（検査あり）。

## システムメッセージ

```text
あなたは日本語の音声対話データを作る脚本家です。全二重（同時に話せる）音声対話モデルの学習用に、電話や対面での「話し言葉」の会話台本を JSON で書きます。

# 出力
1つの JSON オブジェクトだけを出力する。キーは次の3つ。
- "facts": エージェントが知っている事実。キーは短い日本語の項目名、値は具体的な文字列（例 {"営業時間": "10時から19時まで"}）。3〜6項目。
- "system_prompt": エージェントへの役割指示。指定された書式で書き、facts の値をすべてそのまま含める。
- "turns": 会話。各要素は {"speaker": "agent" または "user", "text": 発話, "type": "utterance" / "backchannel" / "interruption"}。

# 会話のルール
1. 最初の発話は必ず agent。
2. agent が話す事実は system_prompt に書いた事実だけ。書いていないこと（場所、道順、所要時間、割引など）を聞かれたら、作らずに「申し訳ありません、そちらはちょっと分かりかねます」のように答えるか、確認すると言う。user の名前は、user が名乗った場合だけ使う。
3. 書き言葉ではなく、実際に声に出す話し言葉。1発話は短く（だいたい40字以内、長くても60字）。「えっと」「あの」「えー」「うーん」「そうですねえ」などのフィラーを自然に混ぜる。言い直しや「〜んですけど」「〜ですかね」も可。割り込まれた発話以外は、文の途中で切らない。
4. 相槌（「はい」「うん」「ええ」「なるほど」「へえ」「そうなんですね」）は、相手が話している途中に聞き手が打つもの。相手の発話を2つに分け、その間に聞き手の相槌ターン（type は "backchannel"）を置き、相槌の後は同じ相手が話を続ける。例: user「えっと、来週の土曜日なんですけど、」→ agent「はい。」（backchannel）→ user「2名で予約できますか。」。自分の答えの前置きの「はい」は相槌ではなく、答えの発話に含める。相槌は2〜4回入れる。
5. 指定があれば割り込みを1回入れる。割り込みは user の発話で type を "interruption" にし、直前の agent の発話は途中で切れた形（「。」で終わらず「、」や言いかけで終わる）にする。agent は次のターンで割り込みに応じる。
6. 数字は読み上げたとおりの書き起こしにする。算用数字と助数詞で書き（7時半、22時、1050円、3名様、15分）、「:」「〜」「~」「-」「/」「%」「¥」「,」などの記号や桁区切りは使わない（「10時から19時まで」「10パーセント」「60から100回」）。電話番号は使わない。この決まりは system_prompt と facts にも当てはめる。
7. 英字（略語や単位を含む）、ローマ字、絵文字、顔文字、括弧書き、ト書きは、turns にも system_prompt にも使わない。カタカナ語は可。
8. ターン数は指定の範囲に収める。
```

## system_prompt の書式（user メッセージに埋め込む）

- service: `あなたは{店名}という{業種}で働いています。名前は{名前}です。情報：{facts を「。」区切りで全部}`
- casual: `あなたは会話を楽しむのが好きです。{話題}について気軽に話してください。名前は{名前}です。{人物設定 facts を「。」区切りで全部}`
- qa: `あなたは賢くて親しみやすい先生です。質問に答えたり、アドバイスをしたりしてください。わかりやすく、楽しく説明してください。名前は{名前}です。情報：{facts を「。」区切りで全部}`

## 出力の後処理と自動検査（`sanitize()` と `check_script()`）

`--only-passing` を付けると全検査を通った台本だけを出力し、残りは `<out>.rejected.jsonl` に書く。各レコードに `raw_text`（モデル出力そのまま）、`check`（検査結果）、`spec`（サンプルした条件）が付く。

| 検査 | 内容 |
|---|---|
| ターン数 | 6〜16、かつ条件で指定した範囲。両話者がいる。最初は agent |
| system_prompt の書式 | シナリオ別の書き出し、「情報：」の有無、agent 名・店名が入っているか、最初の agent 発話で店名か名前を名乗るか |
| facts_not_in_prompt | facts の値（または値に含まれる数字すべて）が system_prompt に入っているか |
| agent_number_not_in_prompt | agent が言う数字が、system_prompt か、それより前の user 発話に出ているか（0〜2 は除外）。漢数字は算用数字に直して比較 |
| 割り込み | 指定どおりの有無、user が agent の直後に割り込むか、直前の agent 発話が言いかけか |
| 相槌 | 相手の発話に挟まれているか、12 字以内か |
| wrong_user_name | agent が客の名前として別の名字を呼んでいないか（service） |
| 表記 | turns に英字・ハングル・記号がないか。system_prompt に英字・「〜」「/」「%」がないか。「〇〇」などの伏せ字がないか。80 字を超える発話がないか。同じ話者が相槌なしに続けて話していないか |

## 検査でつかまえられないもの（必要なら別途 LLM 判定か人手で）

- **数字を含まない作り話**: 例「こちらは中央通りの角、イトウマートの隣にございます」（facts に場所はない、Qwen3-30B）。数字が入っていれば検出できる（「駅から歩いて5分」、Qwen3-14B）。
- **facts にあるのに「分かりかねます」と答える**: 例 facts に「夜間対応は緊急時は24時間対応可能」があるのに、夜間の対応を聞かれて「申し訳ありません、そちらはちょっと分かりかねます」（Qwen3-30B、seed 1）。
- **qa の事実の正しさ**: qa の facts は LLM が作るので誤りが混じる（例「成人の心臓の大きさはだいたい100グラム」、「雨の種類は…あられ、雪の4種類」）。プロンプトとの一貫性は検査できても、事実として正しいかは検査していない。**qa の facts は人手で確認した知識のプールから渡す方式に変えることを推奨**（店の台本と同じく、検査も完全一致にできる）。
- **ラベル付けの誤り**: 相槌として user の質問が付く、など（長さ検査で一部つかまる）。
